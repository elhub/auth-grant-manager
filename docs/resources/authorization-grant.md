# AuthorizationGrant

A grant is a stored permission resulting from an approved request or confirmed
document. Its API resource type is `ConsumableGrant` or `PersistentGrant`.
There is no direct v1 grant-creation operation.

## Identifier

The business identifier of the grant is `id`, a UUID generated by Elhub.
One source can produce several grants, each with its own identifier.

## Attributes

| Name | Description | Format |
|------|-------------|--------|
| `status` | Current state of the grant. | Enum: `Pending`, `Active`, `Exhausted`, `Expired`, `Revoked`. |
| `scopes` | Operations the grant permits and the constraints that apply. | Array of [granted scopes](../concepts/authorization-scopes.md). |
| `validFrom` | Earliest time the grant may be used. | Date-time with offset. |
| `validTo` | Time from which the grant may no longer be used. | Optional date-time with offset; exclusive. |
| `createdAt` | When Elhub issued the grant. | Date-time with offset. |
| `updatedAt` | When Elhub last updated the grant record. | Date-time with offset. |

## Relationships

| Name | Description | Format |
|------|-------------|--------|
| `principal` | Agent whose authority the recipient may exercise. | Agent reference. |
| `grantedBy` | Agent that provided the authorization. | Agent reference. |
| `grantedTo` | Agent that received the permission. | Agent reference. |
| `approvedBy` | Person who approved the request or signed the document. | Person reference. |
| `source` | Approved request or confirmed document that produced the grant. | [AuthorizationRequest](authorization-request.md) or [AuthorizationDocument](authorization-document.md) reference. |

## Status transitions

| From | To | Cause |
|------|----|-------|
| New grant | `Pending` | Approval creates a grant with a future start. |
| New grant | `Active` | Approval creates a grant whose validity has started. |
| `Pending` | `Active` | Start reached while still valid and not revoked. |
| `Pending` or `Active` | `Expired` | Exclusive end reached. |
| `Pending` or `Active` | `Revoked` | Principal, authorizing organization, or system withdraws permission. |
| `Active` consumable grant | `Exhausted` | System records consumption. |

`Revoked`, `Exhausted`, and `Expired` are terminal. Persistent grants cannot be
exhausted. Clients cannot directly set `Pending`, `Active`, or `Expired`.
See [Validity and Time](../concepts/index.md#validity-and-time) for how grant validity differs from proposal validity.

## Use and withdrawal

A grant must be active and cover the principal, recipient, and proposed
action. The consuming service evaluates the grant and performs the authorized
action. Exhaustion and revocation update the grant; they do not undo a
completed action or change the source's status.

Revocation applies to one grant at a time, even if its source produced several.
Updates to a terminal grant are rejected.

## Validation Rules

| Rule key | Rule | Status |
|----------|------|--------|
| AG-VAL001 | An update must use the grant's existing resource type: `ConsumableGrant` or `PersistentGrant`. | DONE |
| AG-VAL002 | Only `Pending` and `Active` grants may be revoked. | DONE |
| AG-VAL003 | Only `Active` consumable grants may be exhausted. | DONE |

## Authorization

### Resource Level Authorization

The default policy is **deny**. The following policies apply to both grant types.

| Policy key | Actor | Policy | Status |
|------------|-------|--------|--------|
| AG-001 | Principal | Read and list grants where it is `principal`, and revoke eligible grants. | DONE |
| AG-002 | Recipient | Read and list grants where it is `grantedTo`. | DONE |
| AG-003 | Grantor | Revoke eligible grants where it is `grantedBy`. | DONE |
| AG-004 | System | Read an individual grant by ID, revoke eligible grants, or mark eligible grants `Exhausted`. | DONE |

Anonymous callers have no policies. Being `grantedBy` or `approvedBy` does
not by itself grant read access. System actors have no unrestricted list
policy. Lifecycle updates do not change scopes, parties, or validity.

### Attribute Level Authorization

There are no attribute-level policies for `AuthorizationGrant`.
