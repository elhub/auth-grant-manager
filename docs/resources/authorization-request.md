# AuthorizationRequest

A request for an authorization, pending acceptance by the party it is requested from. An accepted authorization
request is a valid authorization source in Elhub.

## Identifier

The business identifier of the request is `id`, a UUID generated by Elhub.

## Attributes

| Name                      | Description                                                              | Format                                                      |
|---------------------------|--------------------------------------------------------------------------|-------------------------------------------------------------|
| `requestType`             | Determines the purpose of the request and which grants approval creates. | Enum; see [v1 authorization types](../concepts/authorization-types.md). |
| `status`                  | Current state of the request.                                            | Enum: `Pending`, `Approved`, `Rejected`, `Expired`.         |
| `requestedScopes`         | Permission sought, including any limits on resources or changes.         | Array of [requested scopes](../concepts/authorization-scopes.md). |
| `requestedGrantValidFrom` | Requested start of the resulting grant, not of the request itself.       | Optional date-time with offset; framework agreements only.  |
| `requestedGrantValidTo`   | Requested exclusive end of the resulting grant.                          | Optional date-time with offset; framework agreements only.  |
| `externalReference`       | Reference supplied by the caller and returned unchanged.                 | Optional string.                                            |
| `redirectUri`             | Where the user can be redirected after approving or rejecting.           | Optional absolute HTTPS URI.                                |
| `textReference`           | Identifies the authorization wording associated with the request.        | Server-assigned string.                                     |
| `textLanguage`            | Language of the wording shown when the request was approved or rejected. | Optional language code: `nb`, `nn`, or `en`.                |
| `validFrom`               | When the request becomes open for a decision.                            | Date-time with offset.                                      |
| `validTo`                 | Deadline by which the request must be approved or rejected.              | Date-time with offset; exclusive.                           |
| `createdAt`               | When Elhub created the request.                                          | Date-time with offset.                                      |
| `updatedAt`               | When Elhub last updated the request.                                     | Date-time with offset.                                      |

## Relationships

| Name                  | Description                                             | Format                                                            |
|-----------------------|---------------------------------------------------------|-------------------------------------------------------------------|
| `requestedBy`         | Market entity asking for permission.                    | Market entity reference.                                          |
| `requestedPrincipal`  | Agent whose authority the requester seeks to exercise.  | Agent reference.                                                  |
| `requestedOf`         | Agent asked to provide authorization for the principal. | Agent reference.                                                  |
| `approvedBy`          | Person who approved the request.                        | Person reference; present on approval.                            |
| `authorizationGrants` | Grants issued when the request was approved.            | Array of [grant](authorization-grant.md) references when present. |

## Status transitions

| From         | To         | Cause                                                                          |
|--------------|------------|--------------------------------------------------------------------------------|
| New proposal | `Pending`  | Successful creation.                                                           |
| `Pending`    | `Approved` | Authorized person approves before the deadline; grants are created atomically. |
| `Pending`    | `Rejected` | Authorized person rejects before the deadline; no grants are created.          |
| `Pending`    | `Expired`  | Deadline reached without a decision.                                           |

`Approved`, `Rejected`, and `Expired` are terminal. An approved request stays
approved even when its grants later become unusable.

## Validation Rules

| Rule key  | Rule                                                                                                                                                                         | Status |
|-----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------|
| AR-VAL001 | The authorization type determines which scopes, constraints, and grant dates may be supplied. See [v1 authorization types](../concepts/authorization-types.md).              | DONE   |
| AR-VAL002 | If supplied, `redirectUri` must be an absolute HTTPS URI with a host and without user information or a fragment.                                                             | DONE   |
| AR-VAL003 | Both `requestedPrincipal` and `requestedOf` must resolve to organizations for the supported v1 types.                                                                        | DONE   |
| AR-VAL004 | A decision must be `Approved` or `Rejected`, include a supported `textLanguage`, and be recorded before the deadline while the request is still `Pending`.                   | DONE   |
| AR-VAL005 | If a grant end was requested, approval fails unless it is still after both the approval time and the grant's effective start. See [grant validity](../concepts/index.md#validity-and-time). | DONE   |

## Authorization

### Resource Level Authorization

The default policy is **deny**. The following policies apply to `AuthorizationRequest`.

| Policy key | Actor         | Policy                                                                                                                                              | Status |
|------------|---------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|--------|
| AR-001     | Market Entity | Create a request as the authenticated `requestedBy` for a supported authorization type.                                                             | DONE   |
| AR-002     | Market Entity | Read individual requests and list requests where it is `requestedBy`.                                                                               | DONE   |
| AR-003     | Organization  | Read individual requests and list requests where it is `requestedPrincipal`.                                                                        | DONE   |
| AR-004     | Person        | Approve or reject a request with an end-user token when the Policy Decision Point authorizes the person for `requestedOf` and `requestedPrincipal`. | DONE   |

Anonymous callers have no policies. Being `requestedOf` or `approvedBy` does
not by itself grant read access. There is no policy to delete, cancel, or edit
the proposed scope of a request.

### Attribute Level Authorization

There are no attribute-level policies for `AuthorizationRequest`.
